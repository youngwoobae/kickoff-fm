## 2. 실행 방법

**필요 조건**: Node.js 20.19 이상 (`package.json` `engines`)

```bash
npm install          # 의존성 설치
npm run dev          # 개발 서버 (Vite). 브라우저에서 모바일 크기로 열기 권장
npm test             # Vitest 전체 실행 (vitest run)
npm run build        # 타입 검사 + 프로덕션 빌드 (tsc --noEmit && vite build)
npm run sim:batch    # 엔진 배치 검증 (tsx scripts/sim-batch.ts), 기본 전 시나리오 약 50초
```

그 밖의 스크립트: `npm run typecheck`(타입 검사만), `npm run test:watch`(감시 모드), `npm run preview`(빌드 결과 미리보기).

`sim:batch` 주요 옵션(상세는 `docs/시뮬레이션_검증.md` 7장):

```bash
npm run sim:batch -- --n 2000                       # 시나리오당 2,000경기
npm run sim:batch -- --n 1000 --cap 0.5 --scenario COUNTER_SPREAD
npm run sim:batch -- --n 2000 --strict              # 목표 미달 시 exit 1 (현재 3개 실패로 exit 1)
```

### fake 모드 (UI만 확인할 때)

실제 엔진 대신 UI 개발용 가짜 서비스(`src/ui/dev/fakeService.ts`)로 실행한다. 규칙은 근사치다.

## 4. 미완성·알려진 문제

### 4.1 배치 검증 FAIL 3건과 개선안

원인(`docs/시뮬레이션_검증.md` 6장):

1. **규칙 발동이 드물다.** 규칙은 우리 스타일과 상대 스타일이 동시에 맞을 때만 켜진다. 예: 역습 vs 균형은 한 규칙도 발동하지 않는다.
2. **규칙이 걸리는 결정 지점의 가치가 낮다.** R1(압박)은 가치가 작은 DP1에 걸려 경기당 약 0.06 xG에 그친다.
3. **슬라이더 자체의 트레이드오프가 없다.** 공격 성향 +는 R5에 처벌만 받고 이득이 없다(아키텍처 15장 #5 리스크가 수치로 확인됨).
4. 전술 상한 0.25 / 0.35 / 0.50을 바꿔도 교차검증 차가 2.24 / 2.28 / 2.64%p로 거의 같다. 병목은 상한이 아니다. 따라서 Phase 0 상한 A/B 테스트도 의미 있는 차이를 만들기 어렵다.

개선안(기획 확인 필요):

- ① 슬라이더 고유 효과를 기존 규칙 ID 안의 작은 가산치로 추가 (예: 공격 성향 → DP2·DP4 +0.05×단계, R5로 상쇄)
- ② R1(압박)을 DP8·DP6에도 걸어 턴오버의 가치를 키운다
- ③ COUNTER_SPREAD 판정 기준을 교차검증 값으로 할지, 단순 최대−최소(현재 7.6%p, 목표 하한 10%p에 근접)로 할지 확정

### 4.4 UI ↔ 서비스 계약의 미처리 부족분

계약 1.1.0에서 `submitPlan`의 `origin` 옵션, `remapLineup`(선택 메서드), `logEvent`의 스냅샷 불변 명시를 추가했다. 아직 처리하지 않은 부족분은 다음과 같다.

### 4.5 Phase 0 범위에서 아직 없는 것

- 저장소는 기획서 12.3의 IndexedDB 대신 **localStorage**다(ADR-004, 시즌 말 세이브 약 0.93MB).
- 선택 기능(상대 맞춤 지시 R9·R10 UI 노출 범위, 간이 FA 영입, 주간 훈련 초점)은 구현 여부를 테스터 피드백으로 정한다.
- 플레이테스터 대상 게이트(완주율, 설문, 행동 지표)는 아직 측정하지 않았다(6장).

1. **결정**: N1·N2와 아키텍처 15장 기획 확인 항목(#1~#7)
2. **엔진**: 4.1 개선안 적용 → 배치 FAIL 3건 해소 → COUNTER_SPREAD를 CI 게이트에 추가
3. **자동 운영 검증**: 스모크 관찰 (a)를 배치 시나리오로 재현해 감독 AI 성능을 수동 중앙값의 90~95%로 맞춘다(Q13)

5. **플레이테스트**: 테스터 8~12명, 1~2주 한 시즌, 로그·설문 수집 → 나머지 게이트 판정
