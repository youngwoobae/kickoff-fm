# 접근성·번들 점검 (M7.3)

- 기준: WCAG 2.2 AA (수동 코드 점검 + 브라우저 확인). 번들 목표: Vite 500 kB 경고 해소, 첫 화면 JS gzip 감소, 새 의존성 없음.
- 범위: `src/ui/**`, `index.html`, `vite.config.ts`. 날짜: 2026-10-05, 기준 커밋 484745f.
- 확인 환경: Claude 브라우저 창(375×812 모바일 에뮬레이션, `VITE_DEV_TOOLS=1` 빌드 + `?fake=1`), 헤드리스 Chrome(CDP)로 서비스 워커 확인. Lighthouse 점수는 재지 않았다(남은 일 참고).

## 1. 번들

### 바꾼 것
- `src/ui/app/App.tsx`: 첫 화면(타이틀·홈)에 필요 없는 화면을 `React.lazy` 로 분리 — 커리어·코치실·재정·이적·유스·선발·경기 센터·경기 플랜·팀 전술. 탭 본문 전체를 `Suspense`(로딩 문구 `role="status"`) 하나로 감쌌다.
  - 리그·스쿼드는 홈(`PromotionBanner`)과 편지함(`PlayerSheet`)이 정적으로 쓰므로 첫 청크에 남겼다(Vite "dynamic import will not move module" 경고 없음).
- `vite.config.ts`: `build.rollupOptions.output.manualChunks` — React(`vendor`)와 `src/engine|domain|services|types`(`game`)를 UI 와 다른 청크로. 화면만 바뀐 업데이트 때 vendor·game 은 캐시에 남는다.

### 서비스 워커 프리캐시
- `vite.config.ts` 의 `kickoff-sw` 플러그인은 `generateBundle` 의 모든 산출물(지도 파일 제외)을 넣으므로 새 청크가 자동으로 들어간다. `dist/sw.js` PRECACHE 에 지연 청크 10개 + vendor + game + index 가 모두 있다(파일 21개).
- `vite preview` 빌드본을 헤드리스 Chrome 으로 열어 확인: 서비스 워커가 제어 중(`controlled: true`), 캐시 `kickoff-<버전>` 에 JS 청크 14개 전부.
- **오프라인 재열기**: preview 서버를 끈 뒤(`curl` 000 확인) 같은 프로필로 다시 열었다 → 타이틀 화면이 렌더되고, 지연 청크(`TransferScreen-*.js`)를 동적 import 해도 캐시에서 성공.
- 참고: Claude 데스크톱 브라우저 창은 서비스 워커 등록 자체가 안 된다(“unknown error when fetching the script”, 서버 응답은 200). 앱 문제가 아니라 그 창의 제한이라 헤드리스 Chrome 으로 확인했다.

## 5. 남은 문제
- Lighthouse 접근성 점수(DoD ≥ 90)는 재지 않았다 — M7.5 증거 수집에서 실기기·Lighthouse 로.
- 스크린리더(VoiceOver·TalkBack) 실낭독은 하지 않았다. role·이름은 코드와 DOM 으로만 확인.
- 시트를 연 요소가 동작 결과로 사라지면(예: 방출한 선수 행) 포커스가 `body` 로 간다. 시트 제목이나 목록 머리로 보내는 것이 낫다.
- 탭 알림 점(빨간 점)은 화면에선 색 점만 보인다(버튼 이름에는 사유가 들어감). 시각 사용자를 위한 숫자 배지는 디자인 결정이 필요.
- 2D 피치(SVG)와 선발 피치의 토큰 색(`#facc15` 선택 테두리 등)은 고정색이라 테마 대비 계산 대상에서 뺐다.
- 재계약 창·이적 창이 열린 상태의 2.4.1 흐름은 브라우저로 끝까지 밟지 못했다(타입 검사만).
