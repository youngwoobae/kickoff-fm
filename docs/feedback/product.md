# 제품(PM) 관점 피드백: 기획서_v1 MVP 범위 검토

- 대상 문서: `docs/기획서_v1.md` (중점: 섹션 5 협동, 8 엔진, 11 화면 목록, 12 MVP)
- 검토 기준: 개발 2~4명, 3~6개월(가용 공수 약 6~24 인월)로 만들 수 있는가
- 작성일: 2026-09-26

## 요약 결론

**현재 MVP 정의는 소규모 팀이 3~6개월 안에 만들 수 있는 크기가 아니다.** 제 추정으로는 "라이브 서비스 가능한 MVP"가 약 35~50 인월(엔지니어링만, 아트·기획·QA·운영 별도)이다. 가용 공수의 2~8배다. 확신도는 약 60~70%인데, 팀 숙련도와 기존 자산에 따라 폭이 크기 때문이다.

| 영역 (문서 MVP 기준) | 대략 공수 (인월) | 근거 |
|---|---|---|
| 경기 엔진 + 보정(몬테카를로·CI 보정 테스트) + 승부 요인 리포트 | 3~5 | 엔진 코드는 작지만 8.1 보정 목표 8개를 맞추는 튜닝이 대부분이다 |
| 2D 탑뷰 중계 + 하이라이트 + 모멘텀 | 2~4 | 엔진이 좌표를 만들지 않아서 연출용 위치 생성기를 따로 만들어야 한다 (F-07) |
| 클라이언트 38개 화면 (O 26 + △ 12) | 8~12 | 드래그 편성, 칩 빌더, 바텀시트, 접근성·한 손 모드 포함 |
| 실시간 코치 협동 (잠금·버전·동결·에스크로·되돌리기·로그·채팅) | 5~8 | 실시간 동시성, 권한 매트릭스, 모더레이션까지 포함 |
| 경제 + 이적시장 3채널 블라인드 입찰 + 계약 | 3~5 | 정산 배치, 캡, 낙하산, LP, 이적세, 연관 계정 입찰 차단 |
| 리그 피라미드·봇·봇 인수·재편·정시 배치 스케줄러 | 3~4 | 2:1 재편 불변식, 휴면·복귀 배치 |
| 운영툴 + 악용 탐지 대시보드 + 텔레메트리 | 3~4 | 12.2 운영툴 행 전체 |
| 로그인·IAP·환불·연령 확인·등급분류 대응 | 2~3 | 스토어 2곳 |
| **합계** | **약 29~45 (+통합·QA 20%) ≈ 35~50** | |

문서 전체의 설계 품질(공정성 원칙, 엔진 상한, 설명 가능한 리포트)은 좋다. 문제는 모든 좋은 아이디어가 "MVP"라는 한 칸에 들어가 있다는 점이다. 12.1은 "핵심 루프를 끊는 기능만 넣는다"고 말하지만 12.2 표는 그 원칙을 지키지 않는다. 아래 피드백은 **먼저 무엇을 검증하고, 무엇을 나중으로 미룰지**에 초점을 둔다.

## ① 우선순위별 피드백

우선순위 정의: **P0** = 이 상태로는 일정·가설 검증이 불가능하다. 착수 전에 반드시 결정해야 한다. / **P1** = 범위나 비용을 크게 줄이거나, 명세에 구멍이 있다. 해당 기능 개발 전에 고친다. / **P2** = 개선 권장, 나중에 해도 된다.

## ② 프로토타입 범위 제안

**전제**: 모바일 우선 웹 프로토타입(React + TS + Vite), 로컬 목 백엔드(브라우저 저장소), "다음 날로 넘기기" 버튼으로 하루 경기를 시뮬레이션한다.

**검증할 질문 2개**
- Q-A (H2, 핵심 재미): 상대를 보고 바꾼 전술이 결과와 리포트에서 **보이는가**?
- Q-B (일일 루프): "리포트 → 다음 날 플랜 수정 → 결과"를 26번 반복해도 지루하지 않은가? 체력·로테이션 결정이 매일 의미 있게 생기는가?

**성공 게이트 (제안)**: 테스터 8~12명이 한 시즌(26경기)을 약 1~2주에 걸쳐 플레이한다. 리포트 열람 후 전술을 바꾼 경기가 50% 이상 / "전술이 결과에 영향" 동의 65% 이상 / 시즌 완주 60% 이상 / 몬테카를로 보정 목표(8.1) 충족.

### 프로토타입 구현 메모
- 엔진과 봇 AI, 리그 일정 로직은 **UI에서 분리된 순수 TS 패키지**(`/engine`, `/sim`)로 만든다. CBT 서버에 그대로 옮기는 것이 목표다.
- 목 백엔드도 CBT 서버 API 모양(`submitPlan`, `advanceDay`, `getReport`)으로 인터페이스를 맞춘다. 나중에 fetch 호출로 바꾸기만 하면 되게 한다.
- 개발 순서: ① 엔진 + 몬테카를로 패널(보정이 먼저) → ② 리포트 → ③ 리그 진행 버튼 → ④ 편성·전술 UI → ⑤ 로그 내보내기. ①~②에서 보정 목표를 맞추지 못하면 UI 작업보다 엔진 수정을 먼저 한다.
