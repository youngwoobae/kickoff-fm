# 시뮬레이션 배치 검증 (엔진 0.2.0)

- 대상: 기획서 v2 8.1 보정 목표, 아키텍처 문서 12.1 `sim:batch` 시나리오
- 실행: `npm run sim:batch -- --n 2000 --cap 0.35 --json sim-out/report-0.35.json` (seed 20260926, 기본값)
- 규모: 시나리오당 2,000경기. COUNTER_SPREAD 는 5×5 조합 × 1,000경기 = 25,000경기, RULE_ISOLATION 은 규칙 11개 × 1,000경기 + 2,000경기. 전체 약 5만 경기, 51초
- 합성 팀: `generateSquad` 로 주전 평균 OVR 을 맞춘 22인 스쿼드 30개를 돌려 쓴다(20경기마다 교체). 전술 숙련도 100, 짝수 경기는 X 홈·홀수 경기는 Y 홈
- 아래 수치는 모두 위 명령의 실제 출력이다. 상한 비교(0.25 / 0.5)는 `--n 1000` 으로 따로 돌렸다

## 2. (a) 평균 득점·홈/무 비율

- BASELINE(OVR 60 vs 60, 둘 다 균형 4-4-2, 중립 경기장) 2,000경기: 평균 총 득점 2.670, 팀당 슈팅 13.0, 승/무/패 39.5 / 24.2 / 36.3%. 무승부와 득점은 목표 범위 한가운데다.
- 슈팅 1개당 득점 약 0.10. 슈팅 구성(보정 중 200경기 측정): 코너 약 3.0, 중거리 약 2.0, 역습 약 2.0, 크로스·컷백·스루·개인 돌파 각 1.1~1.5, 직접 프리킥 약 0.8, PK 약 0.14 (팀·경기당).
- 홈 이점(HOME_MOD +0.04 logit)은 작다. 실제 리그 한 시즌(seed 42, 사람 1팀 + 봇 13팀) 182경기 평균 총 득점은 3.03 으로 BASELINE 보다 높다. 봇 전력 차(사람 팀의 0.90~1.08배)와 전술 성향 차이가 섞이기 때문이다.

## 3. (b) 동일 전력에서 전술 상성의 승률 영향

동일 전력(OVR 60), 중립 경기장, 칸마다 1,000경기. 값은 "행 팀의 승 / 무 / 패 %".

| 우리 \ 상대 | 균형 4-4-2 | 점유 4-3-3 | 역습 4-4-2 | 전방압박 4-3-3 | 잠그기 5-3-2 |
|---|---|---|---|---|---|
| 균형 4-4-2 | 35.5 / 27.7 / 36.8 | 35.3 / 23.3 / 41.4 | 35.7 / 23.7 / 40.6 | 33.5 / 27.2 / 39.3 | 33.6 / 24.8 / 41.6 |
| 점유 4-3-3 | 40.1 / 26.2 / 33.7 | 36.8 / 25.1 / 38.1 | 35.1 / 21.7 / 43.2 | 42.6 / 23.5 / 33.9 | 32.7 / 27.6 / 39.7 |
| 역습 4-4-2 | 41.0 / 21.8 / 37.2 | 44.0 / 26.6 / 29.4 | 36.3 / 25.4 / 38.3 | 42.9 / 24.8 / 32.3 | 37.7 / 28.8 / 33.5 |
| 전방압박 4-3-3 | 37.2 / 24.7 / 38.1 | 34.1 / 25.7 / 40.2 | 37.5 / 23.2 / 39.3 | 39.1 / 23.0 / 37.9 | 35.2 / 24.9 / 39.9 |
| 잠그기 5-3-2 | 43.2 / 25.1 / 31.7 | 44.4 / 25.3 / 30.3 | 35.6 / 26.5 / 37.9 | 43.7 / 24.8 / 31.5 | 37.2 / 28.8 / 34.0 |

읽는 법:
- 상성은 존재한다. 예: 역습 vs 점유 44.0 / 29.4(승−패 +14.6%p), 잠그기 vs 점유 44.4 / 30.3, 역습 vs 전방압박 42.9 / 32.3. 반대로 점유는 역습에 35.1 / 43.2 로 진다(R5 역습 처벌, R3 낮은 블록).
- 하지만 크기가 작다. 상대별로 최선과 최악 프리셋의 승률 차는 단순 비교로 2.6~10.3%p(평균 7.6%p)이고, 칸당 표준오차가 약 1.5%p라 최댓값−최솟값은 잡음으로 위쪽으로 부풀려진다.
- 그래서 목표 판정은 **교차검증**으로 했다. 짝수 블록 경기로 최선/최악 프리셋을 고르고 나머지 경기로 승률 차를 잰다. 결과는 평균 2.3%p다(상대별 3.4 / 4.2 / −2.8 / 8.0 / −1.4). 상성의 방향이 안정적인 상대는 전방압박(역습이 +8.0%p)과 점유 정도다.
- 전술 상한을 바꿔도 거의 같다: 교차검증 차 0.25 → 2.24%p, 0.35 → 2.28%p, 0.5 → 2.64%p. 한 결정 지점에서 규칙 합이 상한에 닿는 경우가 드물기 때문이다. **지금 병목은 상한이 아니라 규칙의 발동 빈도와 규칙이 걸리는 결정 지점의 가치**다.

## 4. (c) 전력 차 vs 전술 효과: "전술만으로 결과가 결정되지 않는다"

| 비교 | 강팀 승 / 무 / 약팀 승 (%) |
|---|---|
| 전력 10점 차 (65 vs 55), 둘 다 균형 | 64.3 / 19.9 / 15.8 |
| 같은 대진, 약팀이 최선 카운터(잠그기 5-3-2) | 62.4 / 20.6 / 17.1 |
| 같은 대진, 전술 효과 끔(`tacticsEnabled=false`) | 64.7 |
| 전력 25점 차 (72.5 vs 47.5) | 92.1 / 5.6 / 2.3 |

- 전력 10점 차는 강팀 승률을 동일 전력(39.5%) 대비 약 25%p 올린다. 약팀의 최선 카운터는 이를 약 2%p(64.7 → 62.4) 되돌리는 데 그친다.
- 동일 전력에서 최선/최악 전술 차(교차검증 2.3%p, 단순 7.6%p)는 전력 10점 차 효과(약 25%p)의 1/10~1/3 수준이다. 전력 25점 차는 어떤 전술로도 뒤집히지 않는다(92.1%).
- 결론: **전술만으로 결과가 결정되지 않는다는 조건은 충분히, 오히려 과하게 성립한다.** 기획서가 원하는 "전술이 보이는 차이를 만든다"(동일 전력 10~15%p)에는 못 미친다.

## 6. 전술 효과가 목표에 못 미치는 원인과 다음 작업 제안

1. **규칙 발동이 드물다.** 규칙은 "상대 스타일 + 우리 스타일"이 동시에 맞을 때만 켜진다. 균형(모든 지시 0) 상대에게는 R7(포메이션)·R1(압박) 정도만 걸린다. 예: 역습 vs 균형은 한 규칙도 발동하지 않는다.
2. **규칙이 걸리는 결정 지점의 가치가 낮다.** R1 은 DP1(VALUE 0.022)에 걸려 매 DP1 에 상한까지 걸어도 경기당 약 0.06 xG다. 가치가 큰 DP4·DP5·DP7 에 걸리는 규칙(R3·R4·R6·R5)만 체감된다.
3. **슬라이더 자체의 트레이드오프가 없다.** 기획서 4.4-3 표의 트레이드오프(공격 성향 ↑ = 찬스 ↑ ↔ 역습 허용 ↑ 등) 중 "이득" 쪽은 규칙이 없어 엔진에 들어가 있지 않다. 공격 성향 +는 R5 에 처벌만 받는다(아키텍처 15장 #5 리스크가 수치로 확인됨).
4. 상한(0.25/0.35/0.5) 차이가 결과를 거의 바꾸지 않으므로 Phase 0 A/B 그룹도 의미 있는 차이를 만들지 못할 가능성이 높다.

제안(기획 확인 필요): ① 슬라이더 고유 효과를 기존 규칙 ID 안의 작은 가산치로 추가(예: 공격 성향 → DP2·DP4 +0.05×단계, R5 로 상쇄), ② R1 을 DP8·DP6 에도 걸어 압박의 턴오버 가치를 키우기, ③ COUNTER_SPREAD 기준을 교차검증 값으로 할지 단순 최대−최소로 할지 확정. 단순 최대−최소 7.6%p 는 목표 하한(10%p)에 가깝다.

## 7. 재현 방법

```
npm run sim:batch -- --n 2000                         # 전 시나리오 (약 50초)
npm run sim:batch -- --n 1000 --cap 0.5 --scenario COUNTER_SPREAD,OVR_DIFF_10_COUNTER
npm run sim:batch -- --build-values --n 20000         # VALUE 테이블 재생성
npm run sim:batch -- --n 2000 --strict                # 목표 미달 시 exit 1 (현재 3개 실패로 exit 1)
```

Vitest(`tests/engine/engine.test.ts`)는 BASELINE 1,000경기(득점·무승부·슈팅), OVR_DIFF_25 1,000경기, RULE_ISOLATION(규칙당 200경기)을 매번 검사한다. COUNTER_SPREAD 는 현재 목표 미달이라 CI 게이트에 넣지 않았다.
