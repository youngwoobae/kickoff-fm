## 0. 한 문단 요약 (출시 공지 초안)

> **킥오프 FM v1.0**: 서버도 로그인도 없이 휴대폰 홈 화면에 설치해서 끝까지 즐기는 축구 감독 게임. 5부 루키 리그의 무명 구단을 맡아 매일 경기 플랜을 짜고, 상대를 보고 전술을 바꾸고, 리포트로 왜 이겼는지 확인한다. 선수는 나이를 먹고 성장하고 은퇴한다. 이적 창에서 블라인드 입찰로 선수를 데려오고, 재계약하거나 내보내고, 유스를 키운다. 목표는 여러 시즌에 걸쳐 1부 프리미어 디비전 우승까지 올라가는 것. 친구와는 한 기기에서 번갈아 쥐고 구단주와 코치로 함께 운영할 수 있다. 비행기 모드에서도 된다.

기획서 v2의 Phase 1(CBT 서버)·Phase 2(출시 후보)를 그대로 따르지 않는다. **"한 기기에서 끝까지 플레이 가능한 오프라인 PWA"** 가 v1.0이고, 온라인 대전은 이후 서버 트랙으로 뺀다. 대신 서비스 계약(`GameService`)을 서버 경계로 유지해서 나중에 붙일 수 있게 한다.

## 1. v1.0 정의

### 1.1 제품 정의

| 항목 | v1.0 |
|---|---|
| 형태 | 설치형 웹앱(PWA). 첫 접속 후 네트워크 없이 전체 기능 동작 |

| 외부 의존 | 없음. 서버·로그인·결제·광고·분석 SDK·푸시·CDN 폰트 없음 |
| 저장 | 기기 내 IndexedDB, 세이브 슬롯 3개, 자동 저장, 파일 내보내기/가져오기 |
| 언어 | 한국어 단일, 가상 선수·구단 |

### 1.2 완료 조건 (Definition of Done)

v1.0 태그는 아래 **전부**를 만족할 때만 붙인다. 증거(명령 출력, 스크린샷, 기록)는 Evidence Collector가 `docs/검증_v1.md`에 남긴다.

**기능**
- [ ] 새 게임 → T5 시작 → 자동 진행 스크립트로 **10시즌** 연속 진행 시 예외·교착 0건 (`CAREER_SIM`)
- [ ] 수동 플레이로 **3시즌**(승격 1회 이상 포함) 완주, 콘솔 오류 0건 (375×812 뷰포트, 실제 서비스)
- [ ] 이적 창 2회 이상 입찰·정산, 재계약·방출, 유스 승격, 은퇴 발생을 한 커리어 안에서 확인
- [ ] 시즌 경계에서 실제 티어 이동(사용자·AI 구단 모두)과 순위표·결산 화면 일치
- [ ] 세이브 슬롯 3개 생성·전환·삭제, 탭 강제 종료 후 재실행 시 마지막 처리일 복원
- [ ] 세이브 스키마 2(Phase 0) 파일을 가져오면 스키마 3으로 변환되어 이어서 플레이 가능
- [ ] 첫 실행 튜토리얼을 도움 없이 끝까지 진행 가능, 설정에서 다시 보기 가능

**품질 게이트 (자동)**
- [ ] `npm run typecheck` exit 0, `npm test` 전부 통과, `npm run build` 성공
- [ ] `npm run sim:batch -- --n 2000 --strict` exit 0 (현재 76/80 → 80/80, 기준 변경 시 근거 문서화)

**설치·오프라인**

## 2. 포함 / 제외

### 2.1 포함 (우선순위: P0 = 없으면 v1.0 아님, P1 = 포함 목표, P2 = 일정 밀리면 가장 먼저 자름)

| 기능 | 우선 | 판단 이유 | 마일스톤 |
|---|---|---|---|
| 엔진 미달 항목 정리(포메이션 공평성 3건, 역할 서명 1건) | P0 | 포메이션 5-4-1이 구조적으로 손해면 전술 선택이 거짓말이 된다. 핵심 재미 가설(H2)의 전제 | M1 |
| 자동 운영 성능 검증(감독 AI) | P0 | Phase 0 스모크에서 자동 운영 팀이 강등(관찰 a). 같은 감독 AI가 AI 구단 69개를 운영하므로 커리어 전체 품질을 좌우 | M1 |
| 세이브 슬롯·자동 저장·IndexedDB 전환 | P0 | 다시즌 + 70구단 선수 약 1,600명 + 이적 풀이면 localStorage 5MB와 슬롯 3개를 동시에 못 견딘다(현재 1시즌 0.93MB, 로그 1건마다 전체 저장 m8) | M2 |
| 5티어 피라미드, 실제 승강, 다시즌 커리어(다른 리그는 경량 시뮬) | P0 | "끝까지 플레이"의 끝이 이것이다. 없으면 시즌 2부터 목표가 없다 | M3 |
| 선수 성장·노화·은퇴 + AI 구단 선수단 보충 | P0 | 다시즌에서 선수단이 늙기만 하면 10시즌 안에 게임이 무너진다 | M3 |
| 계약·재계약·방출 | P0 | 성장·노화와 짝. 현재는 "새 시즌 자동 1시즌 재계약"(아키텍처 15장 #7) | M4 |
| 이적시장(AI 선수 풀·블라인드 입찰·이적 창) | P0 | 시즌 사이 할 일의 대부분. 기획서 규칙(7장·9.4)이 이미 정의돼 있다 | M4 |
| 앱 내 받은 편지함(알림 대체) | P0 | 입찰 결과·계약 만료·부상·은퇴를 알릴 통로가 없으면 위 기능이 안 보인다. 비용 작음 | M4 |
| 온보딩 튜토리얼 | P0 | 오프라인 앱은 설명해 줄 운영자가 없다. 오버레이 가이드 6단계(기획서 9.5) | M6 |
| PWA(매니페스트·서비스 워커·오프라인·아이콘) | P0 | v1.0 정의 그 자체 | M7 |
| 부상·징계(경고 누적) | P1 | 부상·퇴장은 이미 있음. 경고 누적은 표시·정지 연결만 | M5 |
| 훈련 포커스(주간) | P1 | 성장 시스템에 손잡이를 하나 준다. 규칙 1개 + 카드 1개 | M5 |
| 유스 아카데미(간이) | P1 | 이적 외 선수 공급원. 시설 등급 없는 연 1회 입단 | M5 |
| 설정 | P1 | 중계 속도, 스포일러, 모션 줄이기, 튜토리얼 다시 보기, 데이터 관리. 로컬 키 1개 | M6 |
| 한국어 문구 다듬기 | P1 | 새 화면이 많이 늘어난 뒤 한 번에 | M6 |
| 성능·접근성 | P1(게이트는 P0) | 측정 후 필요한 곳만 손본다 | M7 |
| 코치 협동(로컬 프로필 핫시트) | P2 | 이미 역할 전환이 있어 프로필 이름·기록 귀속만 추가. 차별점이지만 1인 플레이 완성과 무관 | M6 |
| 2D 탑뷰 경기 연출(엔진 이벤트 기반) | P2 | 기획서가 "2~4인월, 1차"로 분류. 텍스트 중계로 루프는 이미 닫혀 있다. 구역·레인 기반 간이 연출로 제한 | M6 |

**자르는 순서 (일정 초과 시)**: 2D 연출 → 핫시트 프로필 → 유스 → 훈련 포커스. P0는 자르지 않고 일정을 민다.

## 4. 마일스톤

### 4.1 공통 규칙 (사용량 한도로 자주 끊기므로)

- **작업 단위 = 한 에이전트 1회 세션**. 표의 각 줄(M1.1 등)이 한 단위다. 한 단위가 끝나면 반드시 커밋하고 이 문서 7장 체크박스를 갱신한다. 중간에 끊기면 `wip(...)` 커밋으로 상태를 보존한다(기존 관례).
- **계약 먼저**: API가 바뀌는 마일스톤은 첫 단위에서 Backend Architect가 `src/types/**`, `src/services/api.ts`, `docs/아키텍처.md` 16장만 고친다(구현 없음, 선택 메서드 `?`로 추가). 그 뒤 백엔드·프론트 단위가 병렬로 간다.
- **파일 소유권** (아키텍처 0장 A/B 분리 유지)

| 소유자 | 파일 |
|---|---|
| 계약 단위(Backend Architect) | `src/types/**`, `src/services/api.ts`, `src/services/index.ts`, `docs/아키텍처.md` 16장 |
| 백엔드 단위(Backend Architect) | `src/engine/**`, `src/domain/**`, `src/services/*`(api.ts 제외), `scripts/**`, `tests/**` |
| 프론트 단위(Frontend Developer) | `src/ui/**`(fake 서비스 `src/ui/dev/fakeService.ts` 포함), `src/main.tsx`, `index.html`, `public/**` |

| 검증 단위(Evidence Collector·Code Reviewer) | `docs/검증_v1.md`, `docs/코드리뷰.md`. Code Reviewer는 Major 수정만 직접, 나머지는 기록 |

- 프론트 단위는 fake로 개발하되 끝나기 전에 **실제 서비스로 한 번 확인**한다(Phase 0 R2 교훈).
- 모든 새 도메인 규칙은 주입된 `Rng`만 쓴다(결정성). 시즌·일자·구단 ID로 시드를 파생한다.

## 8. 판단 근거와 확신도

- **5티어를 1리그/티어로 줄인 것**(D3·D5)은 가장 큰 판단이다. 기획서 6.1의 2:1 구조(리그 31개, 434팀)는 다수 유저 전제라 오프라인에서는 저장·성능 비용만 크고 플레이 체감은 같다. 확신도 약 80%.
- **AI 구단 영구 존재·승강**(D6)은 기획서 6.4와 반대다. 기획서가 봇을 재생성하는 이유(사람 비율 유지)가 오프라인에는 없다. 서버 트랙에서는 6.4로 되돌린다(`서버_이관_가이드.md`에 명시).
- **IndexedDB 전환은 필요하다.** 1시즌 0.93MB(1리그, 이적 없음)에서 선수 수가 약 5배(70구단 + 이적 풀), 커리어 기록, 슬롯 3개가 붙으면 localStorage 약 5MB를 확실히 넘는다. 확신도 90%.
- **2D 연출은 P2**다. 기획서 스스로 "전술 체감은 리포트가 맡는다"고 정했고, 엔진이 좌표를 만들지 않는다. 구역·레인 간이 연출이 v1의 상한이다.
- 이 순서에서 가장 불확실한 것은 `CAREER_SIM` 판정값이다. 참고할 실측이 없다. M1.3이 가설 값을 정하고 M4.7에서 한 번 고친다고 미리 약속해 둔다.
