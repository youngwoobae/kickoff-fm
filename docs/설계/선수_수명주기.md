## 0. 요약

**핵심 공식 5줄**

1. **성장(주 1회, 시즌 4회)**: `Δ = max(0, K(나이)/4 × M(출전 비중) × F(훈련) + N(0, 0.4))`를 선수의 성장 저금통(`dev.bank`, OVR 단위)에 넣고, 주 포지션 가중 능력치를 1씩 올리며 `5 × 가중치`만큼 꺼내 쓴다. 상한은 `potential`. `K`는 16~18세 5.0에서 24세 1.5로 줄고, 25~27세 0.5, 28세부터 0.
2. **노화(시즌 경계)**: 나이 +1 뒤 `D(나이) = {30:1.0, 31:1.5, 32:2.0, 33:2.5, 34:3.0, 35:3.5, 36+:4.0} + N(0, 0.7)`만큼 저금통에서 뺀다. 신체 능력치(속도·체력·피지컬)가 두 배 잘 깎인다.
3. **은퇴(Day 20 예고, 시즌 경계에 실행)**: 확률 `h(나이) = {33:0.35, 34:0.50, 35:0.65, 36:0.80, 37:0.90, 38+:1.0}`. 소속 티어 기준 OVR 이상인 선수는 ×0.5. 무소속(FA)은 30세 이상이면 한 번의 이적 창 뒤 은퇴, 30세 미만은 2시즌 미계약 시 퇴장.
4. **유스(시즌 시작)**: 구단마다 16~17세 후보 3~5명. `potential ~ N(티어 기준 OVR − 10, 8)`, 후보마다 5% 확률로 +18("보석"). 최대 2명 승격, 20세까지는 성적 부진 방출 대상에서 뺀다.
5. **티어 대역 유지(AI 구단만)**: 주전 11명 평균 OVR이 `기준 +1`보다 높으면 `기준 +4` 이상인 30세 이하 선수를 최대 2명 상위 티어로 내보내고(T1은 해외 이적으로 세계에서 빠짐), `기준 −2`보다 낮으면 FA 풀에서 1명 보강한다. 기준 OVR은 T1 72 / T2 66 / T3 60 / T4 54 / T5 48.

**균형 결과(부록 A 모델, 5시드 × 30시즌)**: 소속 선수가 30시즌 내내 1,540~1,552명(70구단 × 22.0~22.2)으로 유지된다. 시즌당 유입 약 111명(유스 109 + 재생성 3)과 유출 약 110명(소속 은퇴 55 + FA 은퇴 53 + 해외 2)이 맞는다. 티어 평균 OVR은 5시즌 이후 모든 티어·시즌에서 기준 ±1.7 안에 있다.

### 1.2 설계 기둥 (이 시스템이 반드시 주는 경험)

1. **출전 시간이 곧 육성이다.** 같은 유망주라도 뛰게 하면 21세에, 벤치에 두면 25세가 넘어서야 잠재력 근처에 간다. "지금 이길 것인가, 키울 것인가"가 매주 선택이 된다.
2. **나이는 계획을 강요한다.** 30세부터 매 시즌 OVR이 1~4씩 빠지고 33세부터 은퇴한다. 핵심 선수 교체 시점을 한두 시즌 앞서 준비해야 한다.
3. **하위 리그에서도 보석이 나온다.** 유스 후보 20명 중 1명꼴로 티어 기준보다 한참 높은 잠재력을 가진 선수가 나온다. 승격의 동력이 된다.
4. **세계는 무너지지 않는다.** 10시즌, 30시즌을 돌려도 선수 수·나이 분포·티어 전력이 제자리에 있다. 사람이 강해지는 것은 사람의 운영 덕분이어야지 세계가 부풀어서가 아니다.

### 1.3 이 설계서가 정하지 않는 것

- 연봉·유스 연봉·이적료·위약금: M1.3 `docs/설계/오프라인_경제.md`. 이 문서는 "유스 승격 시 계약 3시즌", "재생성 선수 계약 1~3시즌"까지만 정한다.

## 3. 성장

### 3.1 목적과 체감 목표

- **목적**: 잠재력까지 가는 속도를 나이와 출전 시간으로 정한다.
- **플레이어가 느끼는 것**: 매주 월요일(Day 8·15·22)과 시즌 끝에 "+1 패스, +1 시야" 같은 작은 상승이 보인다. 유망주를 선발로 쓰면 한 시즌에 OVR +5~6, 벤치에 두면 +3.
- **결정**: 누구를 뛰게 할지(출전 비중), 어떤 포커스로 어느 능력치를 키울지.

### 3.2 공식

```
주 w의 성장량 (w = 1..4)
  k   = K[age]                          // 3.3 표. 나이는 이번 시즌 나이(경계 전)
  if k == 0 or ovr >= potential or isTemporary: Δ = 0
  s   = 이번 주 출전 시간 / (90 × 이번 주 구단 경기 수)    // 경기 0이면 s = 0
  M   = 0.6 + 0.6 × min(1, s / 0.6)     // 0.60 (미출전) ~ 1.20 (60% 이상 출전)
  F   = FOCUS[focus].growthMult         // 8장. 균형 1.0
  Δ   = max(0, k/4 × M × F + N(0, 0.4))
  dev.bank += Δ
  spendBank(player, FOCUS[focus].attrMult)
```

- `이번 주 출전 시간` = `season.minutes − dev.minutesMark`, 틱 뒤 `dev.minutesMark = season.minutes`.
- 주별 구단 경기 수: W1 7, W2 7, W3 7, W4 5 (Day 22~26). 경기 일정에서 세어도 되고 상수로 둬도 된다.
- FA 풀 선수: `M = 0.6`, `F = 1.0`(균형).
- 부상으로 쉬면 출전 시간이 없으므로 자연히 `M = 0.6`이다. 부상 자체의 추가 벌점은 없다.

### 3.3 나이별 성장 계수 `K` (OVR/시즌, M = 1.0 기준) `[PH]`

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| K | 5.0 | 5.0 | 5.0 | 4.5 | 4.0 | 3.5 | 3.0 | 2.5 | 1.5 | 0.5 | 0.5 | 0.5 | 0 |

근거: 17세·잠재력 60·OVR 38(격차 22)인 유망주가 출전 비중에 따라 아래처럼 자란다(잡음 제외, `F = 1`).

| 나이 | 선발 (M 1.20) | 로테이션 35% (M 0.95) | 벤치 5% (M 0.65) |
|---|---|---|---|
| 17 → 18 | 38 → 44.0 | 38 → 42.8 | 38 → 41.3 |
| 18 → 19 | 50.0 | 47.5 | 44.5 |
| 19 → 20 | 55.4 | 51.8 | 47.4 |
| 20 → 21 | **60.0 (도달)** | 55.6 | 50.0 |
| 21 → 22 | — | 58.9 | 52.3 |
| 22 → 23 | — | **60.0** | 54.2 |
| 24세 말 | — | — | 56.6 |
| 27세 말 | — | — | 57.6 (잠재력 −2.4에서 정체) |

- D20 "성장 ~24세"와 맞는다: 선발로 쓰면 21세, 로테이션이면 23세에 잠재력에 닿고, 거의 못 뛰면 끝내 닿지 못한다.
- 25~27세 `K = 0.5`는 늦게 자리 잡은 선수의 여지다. 28세부터는 성장이 없다(정체 25~29는 "거의 정체").

### 3.4 저금통 소비 `spendBank`

OVR은 정수 능력치의 가중합이라 0.3 같은 성장을 바로 반영할 수 없다. 그래서 OVR 단위 실수 저금통에 모았다가 능력치 1단위씩 바꾼다. 양수면 성장, 음수면 노화(4장)에 같은 함수를 쓴다.

```ts
function spendBank(p: Player, rng: Rng, mult: Partial<Record<AttrKey, number>>): Player {
  const W = OVR_WEIGHTS[p.primary];                 // 주 포지션 핵심 능력치만 바뀐다
  const keys = Object.keys(W) as AttrKey[];
  let bank = p.dev.bank, attrs = { ...p.attrs };
  for (let guard = 0; guard < 60; guard++) {
    if (bank > 0) {
      const cand = keys.filter(k => attrs[k] < 20);
      if (cand.length === 0) { bank = 0; break; }                         // 전부 20
      const k = weightedPick(rng, cand, k => W[k]! * (mult[k] ?? 1));
      const c = 5 * W[k]!;
      if (bank < c) break;                                                // 다음 주로 이월
      if (rawOvr({ ...p, attrs }) + c > p.potential + 0.5) { bank = 0; break; } // 잠재력 상한
      attrs[k] += 1; bank -= c;
    } else if (bank < 0) {
      const cand = keys.filter(k => attrs[k] > 1);
      if (cand.length === 0) { bank = 0; break; }
      const k = weightedPick(rng, cand, k => W[k]! * DECLINE_ATTR_MULT[k]);
      attrs[k] -= 1; bank += 5 * W[k]!;                                   // 넘친 양수는 이월
    } else break;
  }
  const next = { ...p, attrs, dev: { ...p.dev, bank } };
  return { ...next, ovr: computeOvr(next), scoutRange: scoutRangeOf(next) };
}
```

- 비싼 능력치(가중치 0.3 → 비용 1.5)를 뽑았는데 저금통이 모자라면 그 주는 멈추고 이월한다. 평균적으로는 가중치에 비례해 자란다.
- 상한 비교는 반올림 전 원시 OVR로 한다(`+0.5`는 반올림 뒤 `ovr ≤ potential` 보장).
- 핵심 능력치 밖(예: CB의 결정력)은 성장·노화하지 않는다. 포지션 전환 훈련은 범위 밖(18장 U7).

## 5. 잠재력 분포와 스카우트

### 5.1 잠재력 규칙

- `potential`은 선수 생애 동안 **고정**이다(노화는 OVR을 내리지 potential을 내리지 않는다).
- 상한 95, 하한은 현재 OVR.

| 발생 경로 | potential | 비고 |
|---|---|---|
| 새 게임 초기 선수(M3.2) | 기존 `generatePlayer` 규칙 유지: ≤21세 ovr + U{6..16}, 22~24세 + U{2..9}, 25~28세 + U{0..3}, 29세+ = ovr | 초기 과잉 성장은 첫 5시즌에 +1~2 정도로 모델에서 확인(13.3) |
| 유스 후보 | `N(ref(T) − 10, 8)`, 후보마다 5% 확률 +18, [30, 92]로 자름 | 7.2 |
| 재생성 선수(11.4) | 21~24세 ovr + U(0, 4), 25세+ = ovr | 보충용. 기대를 만들지 않는다 |

### 5.2 스카우트 범위 표시

- 기존 `scoutRange = [grade(pot − 4), grade(pot + 4)]`를 나이에 따라 넓힌다: **19세 이하 ±8, 20~23세 ±6, 24세 이상 ±4** `[PH]`. 나이를 먹을수록 범위가 좁아져 "정체가 드러나는" 경험을 준다.
- 경계 ②와 성장 틱마다 다시 계산한다(`scoutRangeOf`).
- 문제: 등급 E는 50 미만 전부라서 T5·T4 유스는 거의 모두 "E~D"로 보인다. 18장 U3에 대안을 적었다.

- 방출 후보는 세계에 남지 않는다(FA 풀에 넣지 않음). 풀이 불어나는 것을 막는다.

- 승격 선수 계약: 3시즌(D19), 연봉은 M1.3 "유스 연봉".

### 7.2 후보 생성 `[PH]`

```
n     = 3 + floor(rng × 3)                          // 3..5
각 후보:
  age   = 16 + floor(rng × 2)                       // 16 or 17
  pot   = ref(T) − 10 + N(0, 8);  if rng < 0.05: pot += 18;  pot = clamp(pot, 30, 92)
  gap   = age == 16 ? U(14, 24) : U(12, 22)
  ovr0  = clamp(pot − gap, 15, 90)
  pos   = weightedPick(POS_WEIGHTS)                 // GK 2, CB 4, FB 4, DM 2, CM 3, AM 2, W 2, ST 3 (기준 스쿼드 22명 비율)
  p     = generatePlayer(rng, pos, round(ovr0), age) 후 potential = round(pot), scoutRange 재계산(±8)
```

- `T`는 **그 시즌 구단의 티어**. 사람이 승격하면 다음 시즌 유스도 좋아진다.
- 기대값(평균 후보 4명 기준, 계산):

| 사건 | 후보 1명 확률 | 시즌당 1명 이상 확률 | 10시즌 안에 1번 이상 |
|---|---|---|---|
| "유망주" pot ≥ ref(T) + 4 | 7.5% (정규 4.0% + 보석 3.5%) | 26.7% | 95.6% |
| "보석" pot ≥ ref(T) + 10 | 2.6% (정규 0.6% + 보석 2.0%) | 10.1% | 65.5% |

  T5(ref 48)라면 유망주는 pot 52 이상, 보석은 pot 58 이상(T4 주전을 넘어 T3 문턱)이다. 네 시즌에 한 번꼴로 쓸 만한 유망주가, 열 시즌 안에 3분의 2 확률로 팀을 한 단계 끌어올릴 보석이 나온다.

### 7.3 사람 구단의 결정

- UI는 후보마다 이름·나이·포지션·현재 OVR·**스카우트 범위만** 보여 준다(`potential` 비노출 원칙 유지).
- 액션: `decideYouth(promoteIds)` (0~2명). 한 번 결정하면 그 시즌에는 되돌릴 수 없다.

### 7.4 AI 규칙 (AI 구단, 사람 미결정 자동 처리 공통)

```
cands = potential 내림차순
taken = 0
for c in cands:
  if taken >= 2 or squadSize >= 25: break
  if squadSize < 22 or (taken == 0 and c.potential >= ref(T) + 4):
     승격(c); taken++
```

- 사람 미결정 자동 처리에서는 `squadSize < 22` 조건을 빼고 유망주 조건만 쓴다(사용자의 선수단 구성을 함부로 채우지 않는다).

## 8. 훈련 포커스

### 8.1 설계 의도

포커스가 **총 성장량**을 바꾸면 "성장 최대 포커스"가 정답이 되어 선택이 사라진다. 그래서 균형·공격·수비·체력은 총량이 같고 **어떤 능력치가 자라는지**만 바꾼다. 엔진은 능력치를 직접 쓰므로(OVR은 안 씀) 이는 곧 전술 성향의 차이다. 전술 숙련·회복은 성장을 깎는 대신 당장의 경기력을 준다. 유망주가 많은 팀은 성장을, 우승 경쟁 중인 팀은 회복을 고르는 긴장이 생긴다.

### 8.2 효과표 `[PH]`

| 포커스 | 성장 배수 F | 능력치 선택 배수 (그룹 ×3, 나머지 ×1) | 매일 효과 |
|---|---|---|---|
| `BALANCED` 균형 (기본) | 1.0 | 없음 | — |
| `ATTACK` 공격 | 1.0 | passing, dribbling, finishing, crossing, vision, kicking | — |
| `DEFENSE` 수비 | 1.0 | tackling, positioning, workRate, reflexes, aerialCommand | — |
| `PHYSICAL` 체력 | 1.0 | pace, stamina, physical | — |
| `TACTICAL` 전술 숙련 | 0.8 | 없음 | 두 슬롯 모두 숙련도 +3/일, 미사용 감쇠(−2/일) 없음 |
| `RECOVERY` 회복 | 0.7 | 없음 | 일일 회복 +4 (기본 +14 + 체력 보정 0~6에 더함) |

- composure는 어느 그룹에도 없다(공수 공통).
- 회복 +4의 크기: 평균 일일 회복 17 → 21, 풀타임 소모 30 기준 지속 가능 출전 비율 57% → 70%. 한 주(7경기) 동안 주전 1~2명을 더 쓸 수 있는 정도다. 대가는 그 주 성장 −30%.
- 전술 숙련: 기본은 사용 +6/경기, 미사용 −2/일. 포메이션을 바꾼 직후(×0.5) 한 주를 쓰면 약 +21 회복된다.
- 28세 이상만 있는 팀에게 공격·수비·체력 포커스는 효과가 없다(K = 0). 이는 의도다. 노장 팀에는 회복·전술 숙련이 맞다.

### 8.3 적용 단위

- 구단 단위 1개. 주 시작(Day 1·8·15·22 00:00)에 `training.next`가 있으면 `training.focus`로 옮긴다. 주 중간 변경은 다음 주부터 적용("변경은 다음 주부터" 표시).
- 성장 틱은 **그 주에 적용된 포커스**를 쓴다.
- AI 구단: 항상 `BALANCED`(비교 기준을 고정해 `CAREER_SIM`을 해석하기 쉽게). 감독 AI 개선은 v1.1.
- 권한: 코치 권한 모델(5.0.4)에서 전술 담당 코치가 제안할 수 있는 항목으로 둔다(M5.1이 `checkAction` 표에 추가).

## 10. 경고 누적 징계

### 10.1 규칙

```
경기 처리 (applyMatchLine 확장):
  y      = line.redCard ? 0 : (line.yellowCards ?? 0)   // 퇴장 경기의 경고는 누적에 넣지 않는다(두 번째 경고 퇴장 포함)
  accum  = (availability.yellowAccum ?? 0) + y
  ban    = 0
  if accum >= 5: ban = 1; accum -= 5                     // 10장째에 다시 1경기
  suspendedMatches = suspendedBefore + (line.redCard ? 1 : 0) + ban

시즌 경계 ⑤: yellowAccum = 0   (D24)
```

- 출장 정지 소화는 기존 로직 그대로(구단이 경기를 치르고 선수가 안 뛰면 −1).

- 현재 `applyMatchLine`은 `suspendedMatches: line.redCard ? 1 : suspendedBefore`로 덮어쓴다. 가산식으로 바꿔야 한다(출전한 선수는 `suspendedBefore = 0`이라 현재 동작과 결과는 같다).
- 편지함: 경고 4장째에 "다음 경고 시 출장 정지" 알림(사람 구단). 정지 확정 시 알림.

## 11. AI 구단 선수단 관리

사람 구단에는 적용하지 않는다(사람은 직접 운영하고, 18명 미만 시 기존 임시 계약 규칙만 적용).

### 11.1 순서 (시즌 경계 ④, 구단 ID 오름차순)

```
aiSquadMaintenance(club, T = 다음 시즌 티어, pool):
  1. 약체 방출       11.2
  2. 대역 상한       11.3   (T1: 해외 이적, T2~T5: 상위 이적 대용)
  3. 대역 하한       11.3
  4. 유스           7.4
  5. 최소 인원 보충  11.4
  6. 최대 인원 정리  11.5
```

`T`는 **승강이 반영된 다음 시즌 티어**다(기획서 6.5 ②에서 확정). 승격한 AI 구단은 새 티어 기준으로 보강되고, 강등 구단은 새 티어 기준으로 정리된다.

### 11.2 약체 방출 `[PH]`

- `age ≥ 21 && ovr < ref(T) − 14` → FA 풀(`faSince = 끝나는 시즌`), 이벤트 `RELEASED`.
- 계약이 남아 있어도 방출한다(AI는 위약금 없이. 18장 U4).

### 11.3 대역 조절 `[PH]`

```
상한: n = 0
  while n < 2 and str(club) > ref(T) + 1:
     x = 30세 이하이면서 ovr >= ref(T) + 4 인 선수 중 OVR 최고   // 없으면 중단
     T == T1 ? 세계에서 삭제(이벤트 SOLD_ABROAD) : FA 풀로(이벤트 SOLD_UP, 상위 티어 구단이 우선 가져감)
     n++
하한:
  if str(club) < ref(T) − 2:
     풀에서 age <= 31, ref(T) − 2 <= ovr <= ref(T) + 6 인 선수 중 OVR 최고 1명 영입(이벤트 SIGNED_FROM_POOL)
```

- 상한 규칙은 "잘 큰 하위 리그 선수는 위로 팔려 간다"를 흉내 낸다. 하한 규칙은 "약해진 구단은 보강한다".
- 이 두 규칙이 없으면 승강 섞임 때문에 하위 티어가 부풀고 티어 간 격차가 줄어든다(T3 +3.5, T4 +3.7, T5 +4.7, 13.3 초안 C).
- 경계 처리 순서상 상한(모든 구단) → 하한(모든 구단)이 되도록 **두 번 순회**한다. 그래야 T5에서 올라온 선수를 T4 구단이 같은 경계에서 데려갈 수 있다.

### 11.4 최소 인원 보충 `[PH]`

```
while size < 22:
  need = 기준 스쿼드 포지션 수(GK 2, CB 4, FB 4, DM 2, CM 3, AM 2, W 2, ST 3) − 현재 주 포지션 수 가 가장 큰 포지션 (동률은 위 순서)

               generatePlayer(rng, need, round(ovr), age), potential = 5.1 재생성 규칙, 이벤트 REGENERATED
```

- 포지션 최소 조건도 함께 확인한다: GK < 2 이면 size와 무관하게 GK 1명 보충(18명 매치데이에 GK 2명 확보).

## 13. 인구 균형 계산 근거

### 13.1 정상 상태 식

소속 선수 수 `N`은 시즌당 유입 `I`와 평균 재적 기간 `L`의 곱이다.

```
N = I × L,   N 목표 = 70 × 22 = 1,540 (AI 최소 인원에 붙어 있다)
```

- 은퇴만으로 나가는 경우의 `L`: 17세 입단부터 32세까지 16시즌 + 33세 이후 기대 2.1시즌(6.2 기본 확률의 생존 곱 합: 1 + 0.65 + 0.325 + 0.114 + 0.023 + 0.002) ≈ **18.1시즌** → 필요한 유입 `I ≈ 85/시즌`(구단당 1.2명).

- 유입 상한: 유스 최대 2명 × 70 = 140/시즌. 하한 방어: 22명 미만이면 재생성이 채운다. 따라서 **고갈은 구조적으로 불가능**하고(재생성이 바닥), **팽창은 25명 상한과 FA 풀 정리로 막힌다**(천장).

```ts
function lifecycleSeasonBoundary(state: GameState, endingSeason: SeasonNo): LifecycleEvent[] {
  const ev: LifecycleEvent[] = [];

  for (const p of allPlayers(state)) if (p.retiring) { removePlayer(state, p.id); ev.push({ kind: 'RETIRED', ... }); }
```

## 부록 A. 인구 모델 스크립트

실행: `node lifecycle_pop.mjs [seed] [seasons] [noBand]` (저장소에는 넣지 않았다. 필요하면 M3.6이 `scripts/`로 옮기거나 `CAREER_SIM`으로 대체한다). 13.2 표는 seed 1~5, 30시즌, 60시즌은 seed 1·2. 13.3 초안 C는 `noBand = 1`.

```js
// 선수 수명주기 인구 모델 (OVR 수준 근사). node lifecycle_pop.mjs [seed=1] [seasons=30] [noBand=0]
const SEED = +(process.argv[2] ?? 1), SEASONS = +(process.argv[3] ?? 30), NO_BAND = process.argv[4] === '1';

const rng = () => { s = (s + 0x6d2b79f5) | 0; let t = Math.imul(s ^ (s >>> 15), 1 | s); t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t; return ((t ^ (t >>> 14)) >>> 0) / 4294967296; };

const mean = (xs) => xs.reduce((a, b) => a + b, 0) / Math.max(1, xs.length);
const REF = [72, 66, 60, 54, 48];

const DECLINE = { 30: 1, 31: 1.5, 32: 2, 33: 2.5, 34: 3, 35: 3.5 }; const declineOf = (a) => (a < 30 ? 0 : DECLINE[a] ?? 4);
const RETIRE = { 33: 0.35, 34: 0.5, 35: 0.65, 36: 0.8, 37: 0.9 }; const hazardOf = (a) => (a < 33 ? 0 : a >= 38 ? 1 : RETIRE[a]);

  const age = clamp(Math.round(25 + gauss() * 4), 17, 35), ovr = clamp(REF[t] + (j < 11 ? 0 : -6) + gauss() * 3, 20, 95);
  const g = age <= 21 ? 6 + rng() * 10 : age <= 24 ? 2 + rng() * 7 : age <= 28 ? rng() * 3 : 0; return mk(age, ovr, clamp(ovr + g, ovr, 95)); }) });

  const st = { retired: 0, faOut: 0, abroad: 0, youth: 0, regen: 0, signed: 0, released: 0, sold: 0 };
  for (const c of clubs) [...c.players].sort((a, b) => b.ovr - a.ovr).forEach((p, r) => { // 주간 성장 ×4 (출전 비중 대용 = 스쿼드 순위)
    const k = GROWTH_K[p.age] ?? 0; if (!k || p.pot <= p.ovr) return; const m = minuteMult(r < 11 ? 0.85 : r < 16 ? 0.35 : 0.05);
    let g = 0; for (let w = 0; w < 4; w++) g += Math.max(0, (k / 4) * m + gauss() * 0.4); p.ovr = Math.min(p.pot, p.ovr + g); });
  for (const p of fa) { const k = GROWTH_K[p.age] ?? 0; if (k && p.pot > p.ovr) p.ovr = Math.min(p.pot, p.ovr + k * 0.6); }

    const h = hazardOf(p.age) * (p.age < 38 && p.ovr >= REF[c.tier] ? 0.5 : 1); if (rng() < h) { st.retired++; return false; } return true; });

    const up = clubs.filter((c) => c.tier === t + 1).map((c) => ({ c, k: str(c) + gauss() * 3 })).sort((a, b) => b.k - a.k).slice(0, 2);
    const dn = clubs.filter((c) => c.tier === t).map((c) => ({ c, k: str(c) + gauss() * 3 })).sort((a, b) => a.k - b.k).slice(0, 2);
    up.forEach((x) => (x.c.nt = t)); dn.forEach((x) => (x.c.nt = t + 1)); }
  for (const c of clubs) if (c.nt !== undefined) { c.tier = c.nt; delete c.nt; }

      c.players = c.players.filter((p) => p !== x); n++; if (c.tier === 0) st.abroad++; else { x.unsigned = 0; fa.push(x); st.sold++; } } }

      const gap = age === 16 ? 14 + rng() * 10 : 12 + rng() * 10; return mk(age, clamp(pot - gap, 15, 90), pot); }).sort((a, b) => b.pot - a.pot);

    while (c.players.length < AI.min) { let j = -1, b = -1; fa.forEach((p, i) => { if (p.age <= AI.faMaxAge && Math.abs(p.ovr - ref) <= AI.faBand && p.ovr > b) { b = p.ovr; j = i; } });
      if (j >= 0) { c.players.push(fa.splice(j, 1)[0]); st.signed++; continue; }
      const age = 21 + Math.floor(rng() * 9), ovr = clamp(ref + AI.regenOff + gauss() * AI.regenSd, ref - 10, ref + 4); c.players.push(mk(age, ovr, ovr + (age <= 24 ? rng() * 4 : 0))); st.regen++; }
    while (c.players.length > AI.max) { c.players.sort((a, b) => a.ovr - 2 * Math.max(0, a.age - 30) - (b.ovr - 2 * Math.max(0, b.age - 30))); const p = c.players.shift(); p.unsigned = 0; fa.push(p); st.released++; } }
  const all = clubs.flatMap((c) => c.players), share = (f) => +(all.filter(f).length / all.length).toFixed(3);

    tiers: [0, 1, 2, 3, 4].map((t) => mean(clubs.filter((c) => c.tier === t).map(str)).toFixed(1)).join('/'), maxOvr: Math.max(...all.map((p) => p.ovr)).toFixed(0) });
}
```

모델과 설계서의 차이(구현 시 주의):
- 모델은 FA 정리에서 `unsigned` 카운터를 경계마다 올린다. 설계서의 `faSince` 규칙(6.3)과 같은 결과다(풀어 준 경계에서는 지우지 않음).
