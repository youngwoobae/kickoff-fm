## 0. 주요 결정 (요약)

| # | 결정 | 이유 |
|---|---|---|
| U1 | 튜토리얼은 **실제 첫 경기일 위에 얹는 오버레이 6단계**. 기획서 9.1의 "봇 상대 튜토리얼 경기 2회"는 만들지 않는다 | 오프라인 v1에서 별도 경기 시나리오(승리 확정 봇, 롱볼 재도전)는 엔진·도메인 작업이 생긴다. 실제 첫 경기 + 리포트로 같은 학습 목표(전술 → 결과)를 달성한다 |

### 1.3 단계별 흐름 (6단계)

각 단계 = 코치마크 1개(대상 요소 강조 + 말풍선). 말풍선 하단 고정 버튼: **[건너뛰기]** (왼쪽, 텍스트 버튼) · **[다음]** (오른쪽, 기본 버튼). 상단에 진행 표시 "2 / 6".

| 단계 | 화면(nav) | 코치마크 대상 `data-tour` | 말풍선 문구 (해요체, 2줄 이내) | 사용자 행동 | 다음 단계로 |
|---|---|---|---|---|---|
| 1 | 홈 `{tab:'home'}` | `home.nextMatch` (NextMatchCard) | **킥오프 FM에 오신 걸 환영해요.** 매일 상대를 보고 경기 플랜을 정한 뒤, 하루씩 넘기며 시즌을 치러요. 이 카드에 다음 상대와 약점이 나와요. | 읽기 | [다음] |
| 2 | 스쿼드 > 선발·벤치 `{tab:'squad', squad:'lineup'}` | `lineup.pitch` → (같은 단계 2번째 말풍선) `lineup.autoRotation` | ① 선수를 탭하고 바꿀 자리를 다시 탭하면 자리가 바뀌어요. ② **자동 로테이션**을 켜 두면 컨디션 70 미만 선발을 경기 전에 알아서 바꿔요. 바쁜 날도 걱정 없어요. | 교환 1회(선택), 자동 로테이션 토글 확인 | [다음] (말풍선 ①→②→단계 3) |
| 3 | 전술 > 팀 전술 `{tab:'tactics', tactics:'team'}` | `tactics.styles` (전술 스타일 카드) | 원하는 **전술 스타일**을 골라 보세요. 포메이션·역할·지시가 한 번에 들어가요. 세부 슬라이더는 나중에 천천히 만져도 돼요. | 스타일 적용(선택) | [다음] |
| 4 | 전술 > 경기 플랜 `{tab:'tactics', tactics:'plan'}` | `plan.default` (추천·기본 플랜 카드) → `plan.submit` (확정 제출 버튼) | ① **기본 플랜**으로 저장해 두면, 제출을 잊은 날에도 이 플랜으로 경기해요. ② 오늘 경기는 **확정 제출**을 눌러 마무리해요. | 기본 플랜 저장 + 확정 제출 | **자동**: `getPlanState().confirmed` 가 생기면. [다음]도 가능 |
| 5 | 홈 `{tab:'home'}` → 하루 결과 시트 | `home.advance` ("다음 날로 넘기기") → 시트 열린 뒤 `dayResult.replay` ("중계 보기") | ① 준비가 끝났어요. **다음 날로 넘기기**를 누르면 경기가 진행돼요. ② 결과가 나왔어요. 중계로 경기를 다시 볼 수 있어요. | 넘기기 → 중계 보기 | **자동**: `nav.tab === 'match'` 가 되면 |
| 6 | 경기 > 리포트 `{tab:'match', matchView:'report'}` | `report.keyFactors` → `report.suggestions` | ① **승부 요인**에서 내 전술이 결과를 어떻게 바꿨는지 볼 수 있어요. ② 다음 경기 제안을 누르면 팀 지시에 바로 반영돼요. 이제 직접 해 보세요! | 읽기 | 리포트 진입 시 말풍선 표시(자동), [완료] → `status='done'` |

**대상이 없을 때(폴백)**: 다음 경기가 없거나(오프시즌·시즌 종료), 대상 요소가 화면에 없으면(코치 역할이라 버튼 비활성 등) 말풍선을 화면 가운데 카드로 띄우고 문구 뒤에 "지금은 경기일이 아니라 다음 경기일에 해 볼 수 있어요"를 붙인다. 진행은 막지 않는다.

**단계 5의 순서 문제**: 단계 4에서 확정 제출 없이 [다음]을 눌러도 단계 5로 간다(기본 플랜으로 경기 — 결정 U2, 기획서 P4 "제출 안 해도 안전하다").

## 2. 설정 화면

### 2.1 진입과 저장

- 진입: 상단 바 ⚙ 버튼(`aria-label="설정"`) → `Sheet`(전체 높이, 제목 "설정"). 타이틀 화면 우상단에도 같은 ⚙ (게임 밖에서는 "게임" 관련 항목 숨김).
- 기존 상단 바 `ThemeToggle`은 설정으로 옮기고 상단 바에서는 뺀다(⚙ 자리). 상단 바 버튼 수 유지.
- 저장: 변경 즉시 저장(저장 버튼 없음). 값은 `kickoff-fm/ui/prefs` 하나:

```ts
// src/ui/prefs.ts (M6.3). 모든 읽기·쓰기는 try/catch, 실패 시 기본값으로 동작
interface UiPrefs {
  v: 1;
  theme: 'system' | 'light' | 'dark';           // 기본 'system'
  fontScale: 1 | 1.125 | 1.25;                  // 기본 1
  motion: 'system' | 'reduce' | 'full';         // 기본 'system' (prefers-reduced-motion 따름)
  replaySpeed: '1' | '2' | '4' | 'instant';     // 기본 '2' (현재 ReplayView 기본값과 같음)
  pitch2d: boolean;                             // 기본 true (2D가 빌드에 있을 때만 의미)
  hideResults: boolean;                         // 스포일러 가리기, 기본 false
  confirmMultiDay: boolean;                     // 여러 날 진행 전 확인, 기본 true
  confirmUnsubmitted: boolean;                  // 플랜 미확정으로 넘길 때 확인, 기본 false
  inboxBadge: boolean;                          // 기본 true
  inboxInResult: boolean;                       // 기본 true
  tutorial: { status: 'new' | 'active' | 'done' | 'skipped'; step: number };
}
```

- 이전: 첫 로드 시 옛 키 `kickoff-fm/ui/theme`이 있으면 `theme`으로 옮기고 지운다(1회).
- `fontScale` 적용 = `<html style="font-size: calc(100% * scale)">`. **전제 작업**: `global.css`의 `font-size: NNpx`를 `rem`으로 바꿔야 효과가 있다(현재 px 고정). 아래 크기에 포함.
- `motion` 적용 = `<html data-motion="reduce">` + CSS `[data-motion=reduce] * { transition:none; animation:none }`. JS 쪽은 `useReducedMotion()` 1개 훅이 `prefs.motion`과 `matchMedia`를 합쳐 판정(현재 `ReplayView`의 직접 `matchMedia` 호출을 이 훅으로 교체).

### 3.4 조사(이/가, 을/를, 은/는, (으)로)

- 변수 뒤 조사는 **받침 판정 함수**로 붙인다. 공백을 넣고 조사를 따로 쓰는 현재 방식("{team} 가", "{name} 는")은 금지.
- UI는 도메인을 import하지 않으므로 함수는 두 곳에 같은 10줄로 둔다: `src/ui/format.ts`의 `josa(word, '이/가')`(B), 도메인 문구용은 A가 `src/domain` 안에 둔다. 숫자·영문으로 끝나면 읽는 소리 기준(1·3·6·7·8·0 받침 있음, L·M·N·R 받침 있음).
- 판정이 어려우면 문장 구조로 피한다: "{team}의 측면 전개가 시작된다", "슬롯 {id} 세이브를 지웠어요".

## 4. 2D 탑뷰 중계 명세 (M6.5, P2 — 일정 초과 시 첫 번째로 자름)

### 4.1 원칙

1. **텍스트 중계가 정본**이다. 2D는 같은 `MatchReplay.lines`를 같은 시계로 그리는 보조 화면이다. 스코어·시간은 항상 현재 줄(`cur`)에서만 읽는다 → 텍스트와 스코어 불일치가 구조적으로 불가능.
2. 엔진·도메인은 바꾸지 않는다. 계약은 **선택 필드 추가만**(4.6). 필드가 없으면(구 세이브·fake) 2D는 "구역 바 수준" 폴백으로 그린다.
3. 무작위 없음. 연출 흔들림(jitter)은 `hash(matchId | lineIndex)`로만 → 같은 경기는 항상 같은 그림.

### 4.2 화면 배치

```
┌ 스코어 바 (기존) ─────────────────────┐
├ 2D 피치 (가로, 폭 100%, 비율 105:68) ──┤  ← 우리 팀 → 공격 방향 (왼쪽에서 오른쪽)
│  ●우리(채운 원)  ○상대(테두리 원)  ◆공  │
├ 재생 컨트롤 (기존 + "2D" 토글) ─────────┤
├ 텍스트 중계 피드 (기존) ───────────────┤
```

- 높이: 343px 폭에서 약 222px. 화면 높이 600px 미만이면 피치를 160px로 줄이고 하프라인 기준 가운데 정렬.
- 우리 팀은 **항상 왼쪽 → 오른쪽 공격**(하프타임 진영 교대 연출 없음 — 단순화, 사용자 혼란 방지). 원정 경기여도 같다.
- 팀 구분: 우리 = 채운 원(액센트 색), 상대 = 테두리만 있는 원(중립 색) → 색 + 모양 병기. 공 = 흰 마름모 + 어두운 테두리.
- 가로 모드(기획서 10.3 "경기 센터 가로 지원")는 ✕ (v1.1).

### 4.3 좌표계와 공 위치 규칙

정규화 좌표 `u`(길이, 0 = 우리 골라인, 1 = 상대 골라인), `v`(폭, 0 = 화면 위, 1 = 화면 아래). SVG `viewBox="0 0 105 68"`, 화면 좌표 = `(u×105, v×68)`.

**공격 팀 기준 → 화면 변환**: 공격 팀이 우리면 그대로, 상대면 `u' = 1 − u`, `v' = 1 − v`(상대의 왼쪽은 우리 화면 아래쪽).

| 구역(공격 팀 기준) | 중심 `u` | 범위 |
|---|---|---|
| Z0 수비 진영 | 0.17 | 0.05~0.33 |
| Z1 중원 | 0.50 | 0.33~0.67 |
| Z2 공격 진영 | 0.80 | 0.67~0.95 |

| 레인(공격 방향 기준) | `v` |
|---|---|
| L 왼쪽 | 0.20 |
| C 가운데 | 0.50 |
| R 오른쪽 | 0.80 |

**공 목표 위치 = 구역 중심 × 레인 + 흔들림**: `u += (h1 − 0.5) × 0.08`, `v += (h2 − 0.5) × 0.10` (`h1`,`h2` = 해시에서 뽑은 0~1). 박스 안 이벤트는 4.4 표의 고정 지점을 쓴다.

**보간**: 이전 공 위치 → 목표 위치를 비트 시간의 60%(최대 600ms) 동안 ease-in-out으로 이동, 나머지 시간은 정지. `pitch`가 없는 줄(교체·경고·조건부 지시 등)은 공을 움직이지 않는다.

**`ballTrack`(선택 필드)이 있으면**: 두 줄 사이 분(minute) 범위에 해당하는 트랙 점들을 비트 시간에 고르게 나눠 차례로 이동(점당 최소 120ms, 넘치면 균등 솎아내기). 없으면 위의 1회 보간.

### 4.5 선수 점 22개 배치 규칙

1. **기본 대형**: `MatchReplay.formations`의 `FormationDef`로 기존 `pitchRows()`(`src/ui/format.ts`, 라인업 화면과 같은 함수)를 써서 6줄(GK·CB·DM·CM·AM·ST 계열)을 얻는다. 줄 → `u`: `[0.04, 0.17, 0.27, 0.36, 0.45, 0.55]`(우리 진영 기준). 줄 안 순서대로 `v`를 `(i+1)/(n+1)`로 균등 분배.
2. **공 따라 이동(블록 이동)**: 매 비트 공 위치 `(bu, bv)`(각 팀 기준 좌표)에 대해
   - 공격 팀: `u += (bu − 0.35) × 0.45`, `v += (bv − 0.5) × 0.25`
   - 수비 팀: `u += (bu' − 0.35) × 0.30` (`bu'` = 수비 팀 기준으로 뒤집은 값 → 공이 자기 진영 깊으면 내려앉음), `v += (bv' − 0.5) × 0.30` (공 쪽으로 좁힘)
   - GK는 `u ∈ [0.01, 0.06]`로 고정 범위, `v`만 공 쪽으로 0.15배 이동.
   - 모든 점 `u ∈ [0.01, 0.97]`, `v ∈ [0.04, 0.96]`으로 자르기.
3. **개인 흔들림**: 점마다 `hash(matchId|lineIndex|slot)`로 ±0.015. 점끼리 겹침 검사는 하지 않는다(22개, 비용 대비 효과 낮음).
4. 화면 변환은 4.3과 같다(상대 팀은 `u' = 1 − u`, `v' = 1 − v`).
5. 강조: `pitch.playerId`가 있고 `starters`로 슬롯을 찾을 수 있으면 그 점에 링. 없으면 강조 없음.
6. `formations`가 없으면(폴백): 양 팀 모두 4-4-2 고정 대형으로 그린다.
7. 조건부 지시로 슬롯 전환(포메이션 변경)은 반영하지 않는다(v1 한계, 문서화만).

**채우는 규칙(백엔드 참고, `commentary.ts`)**

| 줄 | `pitch` 출처 |
|---|---|
| `SHOT`/`GOAL` | 같은 분·같은 팀의 마지막 `DP5`(없으면 `DP4`) `BinaryDecisionLog` → `zone`(없으면 2), `side`(Lane) → `lane`, `chance`; 이벤트의 `playerId`, `onTarget` |
| `OFFSIDE` | `zone: 2`, 같은 분 같은 팀 마지막 결정의 `lane`(없으면 C), `playerId` |
| `LONG_BALL_ADVANCE` / `COUNTER_ATTACK` | `zone: 1`, 같은 분 마지막 결정의 `lane`(없으면 C) |
| 필러(`NEUTRAL`) | 그 5분 구간에서 결정이 많은 팀 = `side`, 그 팀 결정의 최빈 `zone`·`lane`(DP1→0, DP2→1, DP3·DP4→2) |
| `KICK_OFF` | `{ side:'HOME', zone:1, lane:'C' }` |
| 그 외 | 없음 |

**백엔드 작업 추정**: 0.5~1일(이미 로그에 `zone`·`side`·`chance`가 있음, 복사·최빈값만). 계약 버전 2.3.x → 2.4.0, `docs/아키텍처.md` 16장 이력 1줄.

**필드가 없을 때 UI 폴백**: `pitch` 없음 → 현재 세그먼트 `zoneBars` 최댓값 구역 + 레인 C에 공, 팀은 `clubId`로. `formations` 없음 → 4-4-2. 즉 구 세이브·fake 서비스에서도 2D는 동작한다.

### 4.7 시간 압축 (비트 시계)

- 현재 `ReplayView`: 줄 1개당 고정 간격(1× 700ms · 2× 300ms · 4× 110ms · 즉시).
- 변경: **줄 간격 = 속도 기본값 × 가중치**(4.4 표). 2× 기준 한 경기(약 40줄) ≈ 15초, 1× ≈ 35초. 기획서 12분 라이브는 오프라인 버튼 진행(D1)에서는 쓰지 않는다.
- 2D가 켜져 있고 속도가 4×면 보간 시간을 비트의 40%로 줄인다(최소 80ms). "즉시"면 2D는 마지막 줄 상태의 정지 화면.
- 일시정지 = rAF 루프 정지. "결과로" = 마지막 줄 정지 화면.
- 시계는 `ReplayView` 하나가 소유하고 `PitchView`는 `{ lineIndex, line, prevLine, beatMs }`만 받는다(2D가 시계를 따로 가지면 어긋난다).

### 4.8 성능 예산

| 항목 | 예산 / 규칙 |
|---|---|
| 목표 | 60fps, 크롬 CPU 4× 스로틀 · 375×812에서 프레임당 JS ≤ 4ms |
| DOM | SVG 노드 ≤ 80 (선 그리기 약 12 + 점 22 + 공 1 + 강조·아이콘 ≤ 10). `filter`·`blur`·`drop-shadow`·그라데이션 애니메이션 금지 |
| 렌더 | React는 **비트마다 1번만** 렌더(목표 좌표 계산). 프레임 단위 이동은 rAF에서 `ref`로 `<g transform>` 직접 갱신 — 프레임마다 setState 금지 |
| 계산 | 비트당 좌표 계산 O(22). 해시는 FNV-1a 10줄(UI 자체, 엔진 import 금지) |
| 정지 | `document.visibilityState !== 'visible'`이면 rAF 중단, 돌아오면 현재 비트 끝 위치로 점프 |
| 저사양 폴백 | 재생 첫 2초 동안 프레임 간격 평균 > 24ms(≈40fps 미만)면 **스텝 모드**로 전환: 보간 없이 비트마다 위치만 바뀜. 전환은 조용히(토스트 없음), 그 경기 동안 유지 |
| 번들 | `PitchView`는 `lazy()` 별도 청크(첫 로드 JS ≤ 250KB 게이트 보호). 새 의존성 없음 |
| 배터리 | 설정 "2D 경기 화면" 끔 → 컴포넌트 자체를 마운트하지 않음 |

### 4.9 모션 줄이기·접근성

| 항목 | 규칙 |
|---|---|
| 모션 줄이기(설정 또는 OS) | **정지 화면 모드**: 보간·하이라이트·점선 호 없음. 비트마다 공·점 위치만 즉시 갱신. 자동 재생 기본값은 기존처럼 "즉시"(현재 `ReplayView` 동작 유지) |
| 스크린리더 | `<svg role="img" aria-labelledby="pitch-desc">`, `pitch-desc`(시각적으로 숨김)는 비트마다 갱신되는 한 문장: "{분}, {팀} 공격, {공격 진영} {오른쪽}". **live region 아님**(피드·스코어가 이미 알림, 중복 낭독 방지). 포커스하면 현재 상태를 읽음 |
| 정보 등가성 | 2D에만 있는 정보는 없다. 찬스 유형·선수·결과는 모두 텍스트 피드에 이미 있음 |
| 색 | 팀 구분은 채움/테두리 모양 병기, 카드는 모양으로도 구분, 피치 대비: 점 테두리와 잔디 대비 ≥ 3:1(비텍스트 대비 기준) |
| 터치 | 피치는 조작 대상이 아님(탭 동작 없음). 토글은 재생 컨트롤 줄의 "2D" 스위치(44px 이상) |
