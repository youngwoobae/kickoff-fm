## 3. 기준 연봉 S(OVR) 재기준

### 3.1 문제

v2의 `S(OVR) = 0.3M × 1.1^(OVR−50)`은 "T3 천장 OVR 76.4"를 전제로 만든 공식이다. 코드의 OVR 척도는 T3 기준 60, 티어 간 6이다. 이 공식을 그대로 쓰면 T3 기준 스쿼드 22명 연봉합이 **13.39M = 캡 64M의 20.9%**가 되어(스크립트 A) 캡이 아무것도 제한하지 못한다. 현재 `generator.ts`는 S를 쓰지 않고 캡의 94%를 OVR² 가중으로 나눠 준다(`assignSalaries`).

### 3.2 새 공식

```
TIER_GAP = 6                       # 인접 티어 기준 OVR 차 (TIER_REFERENCE_OVR)
G        = 1.55 ^ (1 / TIER_GAP)   # = 1.0758, 티어 배율 1.55를 OVR 6에 나눔
S(OVR)   = 3.0M × G ^ (OVR − 60)   # 1,000 KC 단위 반올림
K_SQ     = 11 + 11 × G^(−6)        # = 18.10, 주전 11 @o + 로테이션 11 @o−6 의 연봉합 = K_SQ × S(o)
천장(캡) = 60 + ln(캡 / K_SQ / 3.0) / ln G
```

S(60) = 3.0M은 "기준 스쿼드가 캡의 약 85%를 쓴다"에서 나온 값이다(0.85 × 64 / 18.10 = 3.006). 여유 15%가 사람·AI 모두의 운영 폭(업그레이드 + 재계약 인상)이다.

**스크립트 A 출력**

| 티어 | 기준 OVR | S(기준) | 22인 연봉합 | 캡 사용률 | 천장 OVR (캡 100%) | 강등 유예 110% 천장 | 0.8S 산입 하한 시 이론 천장 |
|---|---|---|---|---|---|---|---|
| T1 | 72 | 7.21 | 130.43 | 87.0% | 73.91 | 75.22 | 76.97 |
| T2 | 66 | 4.65 | 84.15 | 85.9% | 68.09 | 69.39 | 71.14 |
| T3 | 60 | 3.00 | 54.29 | 84.8% | 62.25 | 63.56 | 65.31 |
| T4 | 54 | 1.94 | 35.03 | 85.4% | 56.16 | 57.46 | 59.21 |
| T5 | 48 | 1.25 | 22.60 | 86.9% | 49.92 | 51.23 | 52.98 |

S 표 (M): 36: 0.52 · 40: 0.70 · 45: 1.00 · 48: 1.25 · 54: 1.94 · 60: 3.00 · 66: 4.65 · 72: 7.21 · 78: 11.17 · 84: 17.32 · 90: 26.84

읽는 법:
- 돈으로 살 수 있는 우위는 **기준 + 약 2 OVR**(캡 천장)까지다. 그 위는 유스 육성·싸게 묶은 재계약(0.8S 하한)으로만 간다. 돈 → 전력 전환의 상한이 캡에 박혀 있어 부익부가 구조적으로 막힌다.
- M1.2가 티어 대역을 바꾸면 `TIER_GAP`과 기준 OVR 60만 바꾸고 나머지는 공식이 따라간다. 캡 사용률 85%를 유지하려면 S(기준 T3) = 0.85 × 캡(T3) / K_SQ.

### 3.3 코드 반영 요지

- `assignSalaries`: 선수별 연봉 = S(OVR) × U(0.9, 1.1)(시드 결정적), 합계 보정 없이 그대로 둔다. 결과적으로 새 게임 시 모든 구단 캡 사용률은 약 85~88%.
- 새 게임 시 모든 구단 시작 잔액 = 해당 티어 이월 상한(배정금 × 20%). 사람 구단에 별도 지원금 없음.

- 강등팀: 무위약 방출권 2장(해당 시즌 한정), 캡 유예 110%. 다음 시즌 Day 1에 캡 산입 합이 캡을 넘으면 D18과 같은 절차로 "캡 초과분만큼 비주전 이적 명단 등록(최저가 0.7V) → 창 종료까지 미해소 시 초과분 선수 출전 불가". 자동 운영 구단은 5.3 AI 매각 규칙으로 창 안에 해소한다.
- **승격 보너스 30% 유지**를 권고한다. D9 기준(승격 직후 강등률 45% 초과 시 조정)에 대해 모델 값은 34.4%다(9.2). 45%·60%로 올려도 32.9%·31.8%로 1~3%p만 내려간다(스크립트 F-2).

## 5. 계약·재계약·방출

### 5.1 공식

```
캡 산입액(p)   = max(p.salary, 0.8 × S(p.ovr)) + p.bonusPerSeason       # 시즌 경계마다 재계산
구단 캡 사용   = Σ 캡 산입액(등록 선수, isTemporary 포함)
캡 한도        = cap(tier) × (강등 시즌 ? 1.10 : 1.00)
연봉 하한      = max(MIN_SALARY 0.2M, 0.9 × S(ovr))                       # 모든 신규·재계약
허용 계약 기간 = 나이 ≤ 23: 1~3 / 24~29: 1~4 / 30~32: 1~2 / ≥ 33: 1        # 계약 시점 나이
```

- 캡 초과가 **재계산**(선수 성장)으로 생기면 그 시즌은 영입·연봉 인상 계약만 막는다(출전 제한 없음).
- 영입·재계약·FA 계약은 "계약 후 캡 사용 ≤ 캡 한도"일 때만 허용.

### 5.2 재계약

```
요구 연봉 ask(p, club) = S(p.ovr) × clamp(m, 0.9, 1.3)
  m = 1.00
    + 0.10  (주전: 이번 시즌 소속 구단 경기의 50% 이상 선발)
    + 0.15  (상위 티어급: p.ovr ≥ REF[club.tier] + 6)
    − 0.10  (31~32세)   − 0.20 (33세 이상)
갱신 보너스   = 0.10 × 새 연봉 × 계약 시즌 수    # 계약 시 즉시 지급(소멸), 캡에는 시즌당 1/시즌수씩 산입
수락 조건     = 제안 연봉 ≥ ask 이고 기간이 허용 범위 안
대상          = seasonsLeft == 1 인 선수, Day 20~27
미처리·거절   = 시즌 경계(Day 28 → Day 1)에서 FA 풀로 이동
```

협상 난수 없음. 같은 입력이면 항상 같은 ask라서 UI가 "요구 연봉"을 그대로 보여 줄 수 있다.

|---|---|---|---|---|---|
| T3 주전 26세 OVR61 | 3.23 | 3.55 | 3 | 1.07 | 3.91 |
| T3 로테이션 24세 OVR55 | 2.08 | 2.08 | 3 | 0.62 | 2.29 |

### 5.3 방출

```
잔여 연봉 = salary × (28 − day) / 28 + salary × (seasonsLeft − 1)
위약금    = 0.5 × 잔여 연봉     # 즉시 지급(소멸). 강등 시즌이면 연봉 전용 계정에서 먼저 차감
면제      = isTemporary, 강등 시즌 무위약 방출권(2장), 유스 후보(승격 전)
결과      = 캡 산입 즉시 해제, 선수는 FA 풀로(시즌 중 방출이면 다음 창부터 입찰 대상)
```

### 5.4 긴급 FA

## 6. 이적시장

### 6.1 평가가치

```
V(p) = 5 × S(p.ovr) × 나이계수 × 잠재력계수 × 계약잔여계수          # 1,000 KC 반올림
나이계수      ≤ 21: 1.3 / 22~27: 1.0 / 28~30: 0.8 / ≥ 31: 0.5
잠재력계수    1 + min(0.45, 0.03 × max(0, 공개잠재추정 − ovr))
계약잔여계수  seasonsLeft ≥ 3: 1.0 / 2: 0.85 / 1: 0.6 (FA·NPC는 3시즌 취급 = 1.0)
```

- **잠재력계수는 숨김 `potential`이 아니라 공개 추정치**(M1.2가 정하는 `scoutRange` → OVR 구간의 중간값)를 쓴다. V는 UI에 보이므로 숨김 값을 쓰면 잠재력이 새어 나간다. AI도 같은 추정치로 평가한다(AI만 진짜 잠재력을 알면 AI 입찰이 정보를 누설한다).
- 등록 후 값 고정: 매물의 V와 가격 범위는 **창 열림(등록) 시점**에 계산해 고정한다.

**스크립트 D 예시**

|---|---|---|---|
| T5 유망주 18세 OVR44, 추정 잠재 +14, 3시즌 | 0.93 | 8.61 | 8.61~11.19 |

### 6.2 매물 3종

| 매물 | 생기는 때 | 가격 | 돈의 흐름 | 창 끝나면 |
|---|---|---|---|---|
| **NPC 신규** (시스템 시장) | 창 열림. 정규 창 티어당 6명(30명), 중간 창 티어당 2명(10명). OVR = REF[t] + 정수 삼각분포(−4~+4), 나이 19~30, 잠재력·포지션은 M1.2 생성기 | 최저 V, 상한 1.3V | 낙찰가 100% 소멸 | 미판매분 삭제(풀에 남기지 않음) |
| **FA** | 시즌 경계(계약 만료), 방출 즉시 | 계약금 0~1.0 × S, 연봉 ≥ 연봉 하한, 기간은 허용 범위 | 계약금 소멸 | 풀에 남음. 정규 창 2회 연속 미계약 또는 31세 이상 미계약으로 시즌 경계를 맞으면 은퇴 처리. 풀 상한 250명(초과 시 OVR 낮은 순 은퇴) |
| **구단 이적 명단** | 사람: 창 기간 수시 등록·철회 / AI: 창 열림 시 7.3 규칙 | 판매자 최저가 0.7V~1.3V, 상한 1.3V | 낙찰가의 90% 판매 구단, **10% 이적세 소멸** | 미판매 시 구단에 남음 |

정규 창에서 만료 선수의 FA 등록은 **Day 28 처리 시점**(재계약 창 Day 27 종료 뒤)이다. 즉 만료 FA는 Day 28·1·2 사흘 입찰받고 Day 2에 정산된다. 계약 잔여 1시즌 선수는 정규 창 구단 명단에 올릴 수 없다(정산 전에 FA가 되므로).

### 6.3 입찰 규칙

| 규칙 | 값 |
|---|---|
| 입찰 | 매물당 구단당 1건, 비공개. 창 안에서 수정·철회 가능. 등록 시 금액을 **예약**(B에서 차감) |
| 이적료 매물 비교값 | 입찰 금액 |
| FA 비교값 | 계약금 + 연봉 × 계약 시즌 수 × 0.5 (v2) |
| FA 예약액 | 계약금 + 연봉 × (남은 일수 / 28) |
| 시즌 영입 한도 | 8명(모든 채널 합, 긴급 FA 제외). 승격팀 승격 시즌 12명. 정규 창은 Day 2 정산이라 **새 시즌** 한도에 잡힌다 |
| 선수단 | 정산 후 25명 초과가 되는 낙찰은 무효 |
| 입찰 허용 | B ≥ 예약 후 합계, 잔액 ≥ 0 (D18 상태면 금지) |

### 6.4 정산 (창 마지막 날 처리, 결정적)

```ts
function settleWindow(state, window, rng /* seed = hash(gameSeed, season, window.kind) */) {
  const listings = openListings(window).sort(byDesc(l => l.maxPrice), byAsc(l => l.id));
  for (const L of listings) {
    let bids = bidsOn(L).sort(byDesc(b => compareValue(L, b)));
    while (bids.length) {
      const top = bids.filter(b => compareValue(L, b) === compareValue(L, bids[0]));   // 1,000 KC 단위 동률
      const hiTier = Math.min(...top.map(b => tierNo(b.clubId)));                    // 1 = T1
      const w = top.map(b => (tierNo(b.clubId) > hiTier ? 2 : 1));                   // 하위 티어 가중 2배 (D17)
      const win = top[weightedPick(rng.fork(L.id), w)];
      if (canComplete(state, win, L)) { complete(state, win, L); break; }            // 성공
      bids = bids.filter(b => b !== win);                                            // 실패 → 다음 순위
    }
  }
  releaseAllReservations(window);   // 진 입찰 예약 해제
  expireNpcListings(window);        // NPC 미판매 삭제
}

function canComplete(s, bid, L) {
  const c = s.clubs[bid.clubId];
  return available(c) + reservation(bid) >= cost(bid)      // 정산 시점 재검증
      && capUseAfter(c, L, bid) <= capLimit(c)
      && squadSize(c) + 1 <= 25
      && signingsThisSeason(c) < signingLimit(c)
      && L.player.clubId === L.sellerClubId;               // 이미 다른 거래로 이동하지 않았음
}

function complete(s, bid, L) {
  pay(bid.clubId, L.kind === 'FA' ? bid.bonus : bid.fee);            // LedgerKind TRANSFER_FEE_PAID / SIGNING_BONUS
  if (L.kind === 'CLUB') { receive(L.sellerClubId, 0.9 * bid.fee); burn(0.1 * bid.fee); }  // TRANSFER_FEE_RECEIVED / TRANSFER_TAX
  movePlayer(L.player, bid.clubId, L.kind === 'FA' ? { salary: bid.salary, seasonsLeft: bid.seasons } : undefined);
  // NPC 신규 계약: salary = S(ovr), seasonsLeft = 허용 최대(≤ 3)
  inbox(...);                                                         // 결과 알림 (M4.2)
}
```

### 6.5 잔액 부족 (D18)

일일 처리 뒤 잔액 < 0 → 즉시 입찰·FA·재계약 인상 금지. 3일째 처리 뒤에도 < 0이면 "연봉이 가장 높은 비주전(최근 5경기 선발 ≤ 2)"부터 **시스템 강제 매각 0.5V**를 잔액 ≥ 0이 될 때까지. 연봉 지급·경기는 멈추지 않는다.

### 6.6 사용자 화면에 보여 줄 값

V, 입찰 범위, 요구 연봉, 캡 산입 예상, B, 예약액, 다음 정산일. **AI 입찰 성향·다른 구단 입찰 수는 보이지 않는다**(블라인드).

## 7. AI 구단 행동

모든 AI 결정은 주입 RNG가 아니라 **해시 균등값** `h(key) ∈ [0,1)`(gameSeed·season·clubId·listingId에서 파생)을 쓴다. 입찰 순서가 바뀌어도 결과가 같다.

### 7.1 성향

```
aggr(club) = 0.5 + 0.5 × h(gameSeed, clubId, 'aggr')    # 커리어 내내 고정, 0.5~1.0
```

### 7.2 이적료 예산

```
B_off   = 잔액 + 한정 예산 + (Day 1 이전이면 다음 배정금 + 승격 보너스)
          − 예약액 − 이번 시즌 남은 연봉 − 다음 시즌 연봉 부채 − 확정 위약금     # v2 7.2 오프시즌 B
정규 창 F = 한정 예산 + aggr × max(0, B_off − 한정 예산 − 0.05 × cap(다음 티어))
중간 창 F = aggr × 0.5 × max(0, B_시즌중 − 0.05 × cap)
강등 시즌: F = min(F, 0.25 × 새 배정금)
```

### 7.3 영입

```
needs      = 포지션 그룹별 최소 인원(GK 2, DF 7, MF 7, FW 4) [PH, M1.2 스쿼드 템플릿과 맞춤] 미달 그룹
weakest(g) = 그룹 g 주전 중 최저 OVR
후보 조건   = (L.ovr ≥ weakest(g) + 2 또는 g ∈ needs) 이고 L.age ≤ 30
              이고 캡 사용(계약 후) ≤ 캡 한도 × 0.97 이고 예약 합 + 예상가 ≤ F
점수        = (L.ovr − weakest(g) + (g ∈ needs ? 10 : 0)) / 예상가
최대 입찰 수 = 중간 창 2 / 정규 창 3 + round(2 × aggr)
입찰가 (이적료) = clamp(round(V × (1 + 0.25 × aggr × h(club, L))), L.minPrice, 1.3V)
입찰 (FA)       = 연봉 S × (0.95 + 0.10 × h), 계약금 S × 0.3 × aggr × h, 기간 = 허용 최대(≤ 3)
```

기대 낙찰가/평가가치 ≈ 1.05~1.15 (aggr 평균 0.75, h 최댓값 경쟁 효과). 경보선 1.20(11장 E5).

### 7.4 매각·방출

```
창 열림 시 이적 명단 등록:
  1) 등록 인원 > 23: 비주전 중 OVR 낮은 순으로 23명이 될 때까지, 최저가 0.8V
  2) 캡 사용 > 캡 한도(경계 재계산 후): 비주전 연봉 높은 순, 최저가 0.7V
  3) 31세 이상 비주전이면서 seasonsLeft ≥ 2: 최저가 0.8V
창 종료 후 인원 > 25: 위약금이 가장 적은 선수부터 방출
시즌 중 방출: 하지 않음(임시 계약 선수 제외)
```

### 7.5 재계약 (Day 20 처리)

```
만료 예정자 중:
  OVR 순위 ≤ 18 이고 나이 ≤ 31 → ask로 재계약, 기간 = min(허용 최대, 3)
  OVR 순위 ≤ 11 이고 나이 ≥ 32 → ask로 1시즌
  나머지 → 재계약 안 함(시즌 경계에 FA)
캡 사용(계약 후) > 캡 × 0.97 이면 OVR 낮은 대상부터 제외
```

### 7.6 유스 (Day 1)

등록 ≤ 22명이면 추정 잠재력 상위 2명, 23명이면 1명, 24명 이상이면 0명 승격. 나머지 방출.

### 7.7 자동 운영 사용자 구단

사람 구단을 감독 AI에 맡기면 위 규칙을 그대로 쓰되 aggr = 0.75 고정(Q13: 수동 중앙값 PPG의 90~95% 목표. 이적은 보수적으로). `CAREER_SIM`의 AGGR 에이전트는 aggr = 1.0, 캡 목표 1.00.

2. **전력 드리프트는 이적이 만드는 +1 OVR 정도의 한 번 이동**이다. 이적 없는 F-3은 기준 ±0.8 안, 이적 있는 F-1은 기준 +0.5~+1.5에서 멈춘다(캡 천장 +2.2가 상한).

5. **"이월 상한 도달 100%"는 오프라인에서는 경보가 아니다.** v2 7.8의 "이월 중앙값 > 상한 80% 3시즌이면 싱크 추가"는 온라인 전제였다. 오프라인에서는 한정 예산 → LP가 설계된 배출구이므로 11장에서는 **잔액 수준의 안정(E2)과 LP 비중(E4)**으로 대신 본다.

## 11. `CAREER_SIM` 판정 기준

- 실행: 새 게임(T5 시작) → 사람 구단을 감독 AI로 자동 운영 → 10시즌. **기본 시드 20개**(`--seeds 20`), 판정은 시드 합산 비율 또는 시드별 분위수.
- `--strict`: **하드 게이트**를 하나라도 넘으면 exit 1. 경고는 출력만.
- XI OVR = 구단별 OVR 상위 11명 평균. REF = `TIER_REFERENCE_OVR`.
- "M3.6"열: 이적 없는 단계(로드맵 M3.6). "M4.8"열: 이적·계약 포함 최종. `—`는 해당 단계에서 측정만 하고 판정하지 않음.
- 모델 값: 9.2 F-1(이적 포함) / F-3(이적 없음). 판정값은 모델 값에 표본 오차(시드 20)와 모델 오차를 더한 여유를 둔 것.

- **AGGR가 AUTO보다 낫지 않다.** 캡이 돈 → 전력 전환을 막기 때문에 "입찰 적극"만으로는 올라가지 못한다. 설계 의도대로다. 따라서 `CAREER_SIM`은 사용자 도달률을 **판정할 수 없다**(전술 기량을 흉내 내지 못함). U1(정체 상한)만 게이트로 두고 도달률은 플레이테스트·`AUTO_VS_MANUAL`로 본다.
- 경제 손잡이(보너스·V 배수)를 모두 당겨도 OPTIMAL T1 도달은 12% → 20%다. **T5 → T1 4회 승격을 10시즌에 해내려면 매 시즌 14팀 중 2위 안에 40% 확률로 들어야 한다**는 구조가 지배한다. 목표 제안과 선택지는 미결정 U-1.
- 제안 목표(가설): OPTIMAL 기준 **10시즌 내 T2 이상 도달 ≥ 40%**, **T1 도달 10~30%**, "한 번도 승격 못 함" ≤ 5%; MEDIAN "한 번도 승격 못 함" ≤ 15%. 현재 모델은 모두 만족.
